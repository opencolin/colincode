Luxor Sandboxes · for coding agents

An agent in a box, one command away.

lux creates or resumes a Luxor sandbox, starts your coding agent in tmux on the inference provider you picked, and puts you straight into it. Name your agents, switch providers without touching a config file, and never hit a paused box.

What you get

The box, and the agent in it.

The Luxor CLI has every primitive: create, resume, exec, ssh, snapshots, volumes. luxcode is the glue that turns them into a coding agent you can reach from anywhere.

The box

Create or resume, never an error

Every command routes through one path that creates a missing sandbox, resumes a paused one and waits out a pending one. Boxes pause by themselves two hours after each create or resume and wake on your next command. New boxes start from a golden image with tmux already in it.

The agent

Your harness, your provider

Pick a terminal agent or a web UI, then the inference provider: the harness default, or Nebius, Boundless, Baseten, Friendli and OpenRouter, written into the harness's own config inside the box. The agent runs in tmux, so it survives disconnects and pauses; lux <agent> drops you back into the same conversation.

Usage

Three commands from zero to a running agent.

$lux help
lux                        pick an agent (or create one) and jump into it
lux new [cli|web|harness]  create: terminal or web → harness → provider → model → size → volume → name
lux <harness> [action]     a harness: your agent for it, or a new one
lux <agent> [action]       a specific agent by name

up        (default)  create or resume the box, start the agent, attach
ssh                  same as up (attach to the running agent)
shell                plain shell in the box
run -- <prompt>      one-shot headless prompt
status               agent, provider, box state
provider             switch inference provider (and model)
model [id]           switch model
size [name]          box size; applies when the box is created
volume [GiB|none]    persistent volume at ~/work: add one, or drop it
url [off]            web UIs: a public Luxor preview link, or remove it
auth                 sign in / store the provider key
down | pause         pause the box (auto-resumed next time)
rm | stop | kill     terminate the box and forget the agent (--purge deletes the volume)

lux ls                     list agents and their boxes
lux pause --all            pause every agent's box
lux rm --all [--purge]     terminate every box and forget every agent
lux image [build [--full]]  the golden image (Luxor base + tmux) new boxes start from
Sizes

small 2 vCPU / 4 GiB · medium 4 / 8 (default) · large 8 / 16 · xlarge 12 / 32 · xxlarge 16 / 64. A box is not resized in place: size applies on the next create.

Volumes

A persistent volume at ~/work (10, 25 or 50 GiB) that survives pause, rm and resizing. The agent starts there. A volume keeps its size for life, so pick generously.

Headless

lux nebius-codex run -- "fix the failing test" runs one prompt and exits. Toolkits take raw arguments: lux tinyfish run -- fetch content get https://…

Pausing

Boxes pause by themselves and wake on your next command

Luxor pauses a box two hours after it was created or last resumed, the workspace cap. Every lux command resumes a paused box first, and the timer starts again. tmux and the agent's session survive it; /tmp and open connections do not. For a job that must run unattended for longer, create the agent with LUXCODE_STICKY=1.

Configuration
LUXCODE_HARNESSclaudeharness used when you omit one
LUXCODE_SIZEmediumdefault box size offered
LUXCODE_VOLUME_GB10default volume size offered (0 = none)
LUXCODE_DISK_GB20root disk
LUXCODE_IMAGE—force one registry image for every harness without its own
LUXCODE_MAX_DURATION2hpause this long after each create or resume (Luxor's cap)
LUXCODE_PAUSE_RETENTION720hhow long a paused box is kept
LUXCODE_STICKY01 creates boxes that never pause by themselves
